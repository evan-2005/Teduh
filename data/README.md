# Data guide

There are two datasets. The app uses **`osm`** by default; set `VITE_DATASET=seed` to use the invented one. The unit tests always use `seed`.

| Folder | What it is |
|---|---|
| `data/osm/` | **Real area** (SS 4, Petaling Jaya): streets, buildings, schools, bus stops and shops from OpenStreetMap, plus modelled shade. Generated by the tools below. |
| `data/seed/` | Small invented neighbourhood with a hand-designed "memorable moment". Always works offline; used by the tests. |
| `data/unit-costs.json` | Unit costs for the fabrication bill of materials, plus `speciesSuggestions`. Shared by both. |

Each dataset folder holds `neighbourhood.json` (paths, destinations and a `meta` block), `journeys.json`, `interventions.json` and, for `osm`, `context.json` (read-only map layers: buildings, parks, mapped trees and landmarks). The app validates all of it on load (`src/data/load.ts`) and shows an error screen naming the problem if something is wrong.

## The real-area pipeline (`data/osm/`)

```bash
npm run data:fetch     # downloads raw OpenStreetMap data into data/osm/raw.json (needs the internet once)
npm run data:build     # builds neighbourhood, journeys, interventions and context from raw.json
npm run test           # checks the result
```

The raw download is committed, so `data:build` works offline.

**Another area:** `npx tsx data/osm/fetch.ts <lat> <lng> <radiusM> <name…>` then `npm run data:build`. The public Overpass servers are often busy; the tool retries and rotates servers for a few minutes.

### What the builder does
1. **Paths:** keeps walkable ways (footways, paths, pedestrian streets, residential and service lanes, roads), removes driveways and tiny dead ends, keeps the largest connected network, and simplifies it into segments of at most 80 m.
2. **Shade (modelled, labelled `estimated`):** for each segment and each of 09:00, 12:00, 14:00 and 17:00 it samples points along the path and asks whether the real sun position (15 October, this latitude) is blocked by a mapped building (7 m high when the height is not mapped) or by a mapped tree's shadow. Covered walkways count as 95% shaded.
3. **Homes and destinations:** two clusters of homes, plus a school or university, a bus stop, a shop, a clinic and a park, chosen so walks are a useful length. Names shown in the app are plain English ("School", "Bus stop"); the official name is kept as a secondary "Local name".
4. **Trips per day:** a rough estimate from the number of buildings near each home cluster.
5. **Candidates:** up to 3 shelters and 5 street-tree rows where exposed paths carry the most trips. Costs come from the same bill of materials the Fabrication panel shows, so the two always agree.
6. **Budget range and demo journey:** derived from the candidate costs.

### Known limits (also shown in the app under "How this was built")
- **OpenStreetMap has no mapped trees for this area.** Tree canopy is therefore missing and shade is understated, especially at midday. This is the gap a field survey fills.
- Buildings have no mapped heights, so a typical two-storey height is assumed.
- Trips, candidate locations and costs are estimates, not measurements or quotes.
- Background map labels (third-party tiles) show local street names. Everything the app itself draws is in English.

### Adding surveyed trees
Put field-surveyed tree locations in `data/osm/surveyed-trees.geojson` (a GeoJSON file of **Point** features) and run `npm run data:build`. They are merged into the shade model and drawn as "Mapped trees".

## The synthetic dataset (`data/seed/`)
Generated once by a script and then edited by hand; it is the stable fixture for tests and offline demos. Replace nothing here unless you also update the seed-specific expectations in `src/lib/routing.test.ts`, `compare.test.ts`, `optimizer.test.ts` and `src/data/load.test.ts`.

## Using your own survey instead
1. Survey on foot: trace every walkable path and each destination; at **09:00, 12:00, 14:00 and 17:00** record each section's shaded fraction (`0`, `0.25`, `0.5`, `0.75`, `1`); note widths and blocked sections.
2. Trace in [geojson.io](https://geojson.io): one **LineString** per path with properties `id`, `widthM`, `shade09`, `shade12`, `shade14`, `shade17` (optionally `accessible: false`, `notes`); one **Point** per destination with `name` and `kind` (`home`, `school`, `bus-stop`, `shops`, `clinic`, `park`).
3. Convert: `npx tsx data/convert-geojson.ts traced.geojson data/<your-folder>/neighbourhood.json`. Segments missing a shade value are written as `shadeSource: "missing"`.
4. Write `journeys.json`, `interventions.json` and a `meta` block by hand (copy the shape from `data/seed/`), then add your folder name to `DatasetName` in `src/data/load.ts`.
